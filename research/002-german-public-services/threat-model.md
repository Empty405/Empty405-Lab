# Threat Model

The project does not assume that every risk comes from an external attacker.

## Threat actors and failure sources

- external attacker
- malicious insider
- over-privileged employee
- under-privileged employee unable to access required records
- accidental employee error
- incorrect routing
- stale or inconsistent records
- software defect
- configuration error
- broken identity mapping
- incomplete departmental transfer
- missing audit trail
- inaccessible communication channel
- language barrier
- process or training failure

## Security properties

### Confidentiality
Can information be accessed only by authorized parties?

### Integrity
Can records be modified, lost, duplicated or incorrectly associated?

### Availability
Can an entitled person reliably access the service and their administrative rights?

### Accountability
Can actions be attributed to an actor, system and time?

### Traceability
Can the lifecycle of a message, document or decision be reconstructed?

### Accessibility
Can users realistically exercise their rights despite language, disability or digital barriers?

### Administrative consistency
Does the same case remain coherent when responsibility changes?
