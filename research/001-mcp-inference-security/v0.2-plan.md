# Research #001 — v0.2 Plan

## MCP Inference Security Stress Test

**Project:** Empty405 Lab  
**Research:** 001  
**Version:** v0.2  
**Status:** Experimental extension  
**Relationship to v0.1:** additive; v0.1 remains unchanged

---

## Objective

Version 0.1 showed, in a nine-cell synthetic environment, that a patient observer could eventually recover the same information under a conventional time-window rate limiter as under the unrestricted baseline, while cumulative structural-coverage policies changed the final reconstruction outcome.

Version 0.2 asks a harder question:

> Does that distinction survive when the hidden state is larger, changes over time, is exposed through multiple heterogeneous tools, and is queried by observers that can rotate identities?

The goal is not to validate a production defense.

The goal is to stress the original mechanism until it fails or produces a more precise research question.

---

## Changes from v0.1

v0.2 introduces:

1. a larger hidden state;
2. multiple time windows;
3. four heterogeneous tool projections;
4. randomized query order;
5. a stronger constraint-composition observer;
6. multiple identities;
7. identity rotation;
8. per-identity and shared-principal exposure budgets;
9. a separate task-utility metric;
10. repeated randomized trials;
11. new figures for information exposure, utility, and identity-rotation behavior.

---

## Hidden State

Each trial creates a synthetic state with:

```text
12 locations
×
8 resources
×
3 time windows
=
288 hidden cells
```

Each hidden cell contains an integer value from 0 to 100.

The state changes across time windows using a bounded random walk rather than being regenerated independently.

This creates limited temporal structure while remaining simple enough to reproduce.

---

## Tool Projections

The observer never receives the hidden value directly from a single unrestricted tool.

Four tool schemas expose different projections of the same state.

### 1. Availability

Returns whether the value is above a threshold.

Example:

```text
available = true
```

### 2. Capacity Band

Returns a coarse category:

```text
low
medium
high
```

### 3. Numeric Range

Returns a quantized numeric interval.

Example:

```text
70–79
```

### 4. Trend

Returns the direction of change relative to the previous time window:

```text
up
down
stable
```

These tools deliberately overlap.

The experiment therefore tests cross-tool composition rather than direct secret retrieval.

---

## Observer

The v0.2 observer is stronger than the v0.1 deterministic mapping.

For each hidden cell, it maintains a candidate interval:

```text
[0, 100]
```

Every permitted tool response narrows that interval.

Examples:

```text
available = false
→ upper bound decreases

capacity = high
→ lower bound increases

range = 70–79
→ interval becomes [70, 79]

trend = up
→ current interval is constrained relative to the previous interval
```

The observer combines all available constraints and estimates the hidden value using the midpoint of the surviving interval.

This is still not an optimal statistical attacker, but it is materially stronger than v0.1.

---

## Identity Models

The benchmark tests two identity conditions.

### Single identity

All queries originate from one client identity.

### Rotating identities

Queries are distributed across four identities:

```text
observer-0
observer-1
observer-2
observer-3
```

The identities rotate deterministically through the randomized query stream.

This models a simple budget-reset attack.

It does not model a full Sybil ecosystem or identity attribution problem.

---

## Defense Modes

### Baseline

No cumulative exposure control.

### Rate Limit + Waiting

A conventional request-frequency limit is modeled under the same patient-observer assumption as v0.1.

The observer can wait for the window to reset.

Therefore the limiter affects collection time but does not permanently remove queries from the final information set.

### Hard Exposure Budget — Per Identity

Each identity receives an independent cumulative budget.

A new hidden cell consumes one budget unit for that identity.

This is intentionally vulnerable to identity rotation.

### Hard Exposure Budget — Shared Principal

All identities in the experiment map to one shared principal exposure ledger.

Rotating identities therefore does not reset the cumulative budget.

This mode tests whether the defense depends on stable accounting scope.

### Adaptive Disclosure — Shared Principal

The same shared cumulative ledger is used, but precision degrades as exposure grows.

Conceptually:

```text
low exposure
→ original tool response

moderate exposure
→ coarser response

high exposure
→ limited response
```

This tests whether utility can be retained without returning to unrestricted disclosure.

---

## Exposure Budget

The hard shared-principal policy uses a cumulative budget proportional to the 288-cell hidden state.

The exact benchmark configuration is recorded in:

```text
results/benchmark-v0.2.json
```

The important property is that the budget does not reset when the client waits.

For the shared-principal mode, it also does not reset when the observer changes among the four modeled identities.

## Metrics

v0.2 separates information exposure from task utility.

### Information Exposure

For each hidden cell, the observer begins with uncertainty width:

```text
100
```

After collecting permitted observations, the remaining candidate interval has width:

```text
w
```

Cell information exposure is approximated as:

```text
1 - (w / 100)
```

The final metric is the mean across all hidden cells.

This is a structural experimental metric, not mutual information and not a differential-privacy guarantee.

### Reconstruction Error

The midpoint estimate of each surviving interval is compared with the true hidden value.

Mean absolute error is recorded as a secondary metric.

### Task Utility

A legitimate client workload is defined separately from the attacker’s full-state reconstruction objective.

The workload requests a small subset of operational answers distributed across locations, resources, and time windows.

Utility is the fraction of those task queries that receive a response precise enough to satisfy the synthetic task.

This prevents “security” from being measured only as denial.

---

## Hypotheses

### H1

Under a patient observer, conventional time-window rate limiting will not materially reduce final information exposure relative to baseline.

### H2

A hard cumulative budget tied only to client identity will weaken substantially when identities rotate.

### H3

A shared-principal cumulative budget will remain effective under the modeled identity rotation.

### H4

Adaptive disclosure will preserve more legitimate task utility than hard blocking while still reducing information exposure relative to baseline.

---

## Failure Conditions

The v0.2 concept should be considered weakened if:

- the stronger observer reconstructs nearly the same state under shared exposure controls as under baseline;
- identity rotation defeats both per-identity and shared-principal accounting;
- adaptive disclosure provides little utility advantage over hard blocking;
- the measured differences disappear as state size increases;
- results depend strongly on one random seed or one query ordering.

## Expected Research Value

The most useful possible outcome is not necessarily that the v0.1 mechanism succeeds.

A failure can identify the actual boundary of the idea.

In particular, identity rotation may reveal that cumulative exposure accounting is meaningful only when the system can define a stable accounting principal across sessions, tokens, tools, or servers.

That would shift the research question from:

> Should requests be counted differently?

Toward:

> What entity should cumulative information exposure be attributed to in an agentic tool ecosystem?

That is the central stress test introduced by v0.2.
